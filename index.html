Jak działają algorytmy

      
Wpisy to lista rekordów z niezmiennym ID, datą, godzinami, przerwą i opisem. Godziny zamieniamy na minuty od północy; odejmujemy przerwę, a nie zapisujemy czasu jako HH.MM. Przedziały tego samego dnia konfliktują, gdy startA < koniecB i koniecA > startB. Równe granice są dozwolone.

      
Sortowanie przez wstawianie

      
dla i = 1 .. n−1:
  klucz = lista[i]; j = i−1
  dopóki j ≥ 0 i lista[j] > klucz:
    lista[j+1] = lista[j]; j = j−1
  lista[j+1] = klucz

      
Porównujemy kolejno datę, start i ID. Licznik na stronie jest liczbą rzeczywistych porównań klucza w ostatnim renderowaniu. Wyszukiwanie liniowe zwraca wszystkie dopasowania, więc sprawdza każdy rekord. Sumowanie minut oraz sprawdzanie konfliktów przechodzą po odpowiednich rekordach.

      
Wyszukiwanie liniowe

      
wyniki ← pusta lista
dla każdego wpisu:
    zwiększ licznik sprawdzonych wpisów
    jeżeli opis zawiera szukaną frazę (bez różnicy wielkości liter):
        dodaj wpis do wyników
zwróć wyniki

      
Przykład sortowania przez wstawianie

      
Klucz: data → godzina początku → ID. Wejście C, A, B ma wynik A, B, C.

      
PrzedDecyzjaPo

        
C, A, BWstaw A: porównaj C z A; 03.11 > 02.11, więc przesuń CC, C, B

        
C, C, BBrak dalszych rekordów po lewej; umieść A na początkuA, C, B

        
A, C, BWstaw B: C ma późniejszą datę; przesuń CA, C, C

        
A, C, CA ≤ B według klucza; umieść B po AA, B, C

      

      
PrzedDecyzjaPo
A 09:00–10:00Wstaw B 10:00–10:30; 10:00 < 10:00 jest fałszemA, B — dozwolone stykanie
B 10:00–10:30Wstaw C 10:20–11:00; 10:20 < 10:30 oraz 11:00 > 10:00Konflikt — odrzuć bez zmiany listy
Lista posortowanaPorównaj kolejne kluczeWynik według daty → startu → ID

      
Złożoność: sortowanie O(n²) w najgorszym i O(n) w najlepszym przypadku; implementacja tworzy kopię listy, więc pamięć O(n). Wyszukiwanie i sumowanie O(n), pamięć wyszukiwania O(k) dla k wyników. Raport liczników dla 10/100/1000 rekordów i obu kolejności znajduje się w pliku BENCHMARK.md.
